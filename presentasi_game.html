POS 01 • LAPISAN 1: IOT SENSOR VALLEY • LATAR BELAKANG

Hybrid Markov Chain-Based Dynamic Scheduling (HMCDS)

Jurnal Referensi: "Hybrid Markov chain-based dynamic scheduling to improve load balancing performance in fog-cloud environment"
Penulis: Navid Khaledian, Shiva Razzaghzadeh, Zeynab Haghbayan, & Marcus Völp (University of Luxembourg & Islamic Azad University)
Publikasi: Sustainable Computing: Informatics and Systems (Elsevier), Vol. 45, Article 101077, 2025 • doi:10.1016/j.suscom.2024.101077

Dalam ekosistem Internet of Things (IoT), penggunaan Cloud Computing murni memicu latensi tinggi karena jarak fisik ke pusat data. Fog Computing mendekatkan pemrosesan ke tepi jaringan (network edge), namun kapasitas CPU & memorinya terbatas. Tanpa penjadwalan adaptif, sistem mengalami 3 masalah utama:

1. Load Instability

Ketidakstabilan beban kerja yang memicu bottleneck (kemacetan komputasi) pada node tertentu.

2. Makespan & Delay Tinggi

Membengkaknya waktu selesai total dan tunda antrean; fatal bagi aplikasi real-time (kendaraan otonom, medis, otomasi industri).

3. Underutilization of VM

Sebagian VM mengalami overload sementara VM lain menganggur (idle), sehingga memboroskan energi.

INTI POS 1
HMCDS hadir memadukan prediksi beban proaktif (Markov Chain) dan optimasi pemetaan global (AOA) untuk menstabilkan lingkungan Fog–Cloud.
POS 02 • GERBANG CF_MANAGER • ARSITEKTUR 3 LAPIS

Three-Layer Architecture & Klasifikasi Tugas

1. IoT / Sensor Layer

Perangkat pintar & sensor menghasilkan permintaan tugas (tasks) dengan karakteristik heterogen.

2. Fog Layer (CF_Manager)

15 VM (100–2.800 MIPS, RAM 0,5 GB, Storage 10 GB, BW 1 GB/s). Bertugas memantau sumber daya & mengklasifikasikan tugas.

3. Cloud Layer

2 Data Center, 4 Host, 40 VM (3.000–5.000 MIPS, RAM 1 GB, Storage 20 GB, BW 0,5 GB/s) untuk tugas non-real-time & backup.

Kriteria Klasifikasi Tugas oleh CF_Manager

Urgensi (Deadline):
  • Real-Time: Wajib diproses langsung di Fog Layer terdekat (latensi minimal).
  • Non-Real-Time: Toleran jeda, didistribusikan ke Fog & Cloud Layer.
Kebutuhan Sumber Daya:
  • Lightweight: Dieksekusi di edge / fog.
  • Heavyweight: Dialokasikan ke fog node besar atau cloud.
Ketergantungan (Dependency):
  • Independent tasks: Dapat dijadwalkan paralel.
  • Dependent tasks: Dimodelkan dengan Directed Acyclic Graph (DAG).
INTI POS 2
Pemisahan tugas Real-Time (khusus Fog) vs Non-Real-Time (Fog + Cloud) memastikan batas tenggat waktu terjaga sebelum optimasi dimulai.
POS 03 • FOG PLATEAU • TAHAP 1: MARKOV CHAIN

Prediksi Beban VM dengan Markov Chain (VM Load Forecasting)

Markov Chain bersifat memoryless (status masa depan $t+1$ hanya bergantung pada status saat ini $t$), sehingga komputasi prediksinya sangat ringan tanpa perlu melatih model Machine Learning yang berat.

1. Beban Tugas & Total Beban VM: $$L_i(t) = \lambda_1 E_i(t) + \lambda_2 W_i(t), \quad \sum \lambda_k = 1$$ $$\text{LOAD}(i) = \sum_{k=1}^{n} L_k(t)$$
2. Klasifikasi 3 Status VM:
  • V1 = N : Normal Load
  • V2 = U : Underloaded / Low Load (L)
  • V3 = O : Overloaded / High Load (H)
3. Matriks Probabilitas Transisi (Transition Probability Matrix): $$P_{ij}(t) = P\{X_{n+1} = j \mid x_n = i\}, \quad \sum_{j=1}^{N} a_{ij} = 1 \qquad\text{dan jalur multi-langkah:}\qquad P_{ij} = \sum_{t=2}^{n} \frac{P_{ij}^{(t)} + P_{ji}^{(t)}}{2}$$
Aturan Low-Load ($P_{ij} \le \text{MIN}(d_i)$)

VM diprediksi berstatus Low-Load $\rightarrow$ aman menerima tugas baru atau tugas limpahan migrasi.

Aturan Overloaded ($P_{ij} \ge \text{MAX}(d_i)$)

VM diprediksi akan Overloaded $\rightarrow$ sistem segera memigrasikan tugas ke VM Low-Load hingga kembali ke rentang $\text{NORMAL}(i)$.

POS 04 • FOG PLATEAU • TAHAP 2: ARITHMETIC OPTIMIZATION ALGORITHM

Optimasi Penjadwalan Menggunakan AOA

1. Fungsi Objektif (Fitness Function): $$\text{ETC}_{ij} = \frac{T_{len}^i}{VM_{pow}^j} \qquad | \qquad \text{Cost}_{\text{fog}} = \min \left( \max_{j \in \{1..m\}} \sum_{i=1}^{n} \text{ETC}_{ij} \right) \qquad | \qquad F = \alpha \times D + (1 - \alpha) \times E$$
2. Parameter Pengendali Pencarian ($\text{MOA}$ dan $\text{MOP}$, dengan $\alpha = 5$): $$\text{MOA}(C\_Iter) = \text{Min} + C\_Iter \times \left( \frac{\text{Max} - \text{Min}}{M\_Iter} \right) \qquad\text{dan}\qquad \text{MOP}(C\_Iter) = 1 - \frac{C\_Iter^{1/\alpha}}{M\_Iter^{1/\alpha}}$$
3a. Fase Eksplorasi ($r_1 > \text{MOA}$) — Global ($\div, \times$): $$X_{i,j}(C\_Iter+1) = \begin{cases} best(x_j) \div (\text{MOP} + \epsilon) \times ((UB_j - LB_j)\mu + LB_j), & r_2 < 0.5 \\ best(x_j) \times \text{MOP} \times ((UB_j - LB_j)\mu + LB_j), & r_2 \ge 0.5 \end{cases}$$
3b. Fase Eksploitasi ($r_1 \le \text{MOA}$) — Lokal ($-, +$): $$X_{i,j}(C\_Iter+1) = \begin{cases} best(x_j) - \text{MOP} \times ((UB_j - LB_j)\mu + LB_j), & r_3 < 0.5 \\ best(x_j) + \text{MOP} \times ((UB_j - LB_j)\mu + LB_j), & r_3 \ge 0.5 \end{cases}$$

Keterangan: $UB_j, LB_j$ adalah batas atas & bawah indeks VM, $\mu$ parameter kontrol, dan $\epsilon \approx 0.001$ pencegah pembagian dengan nol.

POS 05 • JEMBATAN FOG–CLOUD • ALUR EKSEKUSI HYBRID

Pseudocode Terintegrasi HMCDS (5 Langkah)

ALGORITHM: HMCDS (Hybrid Markov Chain + AOA) • N_pop = 10, M_Iter = 30, alpha = 5, eps = 0.001 
STEP 1: Klasifikasi Tugas & Pemantauan Beban (Fog Broker)
  1. Pisahkan Real-Time (kandidat = Fog Layer) & Non-Real-Time (kandidat = Fog + Cloud).
  2. Hitung beban terkini tiap VM: LOAD(i) = sum(lambda_1 * E_i(t) + lambda_2 * W_i(t)).

STEP 2: Prediksi Status VM dengan Markov Chain
  1. Bentuk Matriks Probabilitas Transisi P_ij dari riwayat transisi beban VM.
  2. Klasifikasikan prediksi:
     - P_ij <= MIN_threshold -> LOW_LOAD (Prioritas penerima tugas)
     - MIN < P_ij < MAX      -> NORMAL
     - P_ij >= MAX_threshold -> OVERLOADED (Keluarkan dari kandidat / migrasikan tugas)

STEP 3: Inisialisasi Populasi AOA
  1. Bangkitkan N_pop (10) vektor solusi X_i (memetakan Task_k ke VM valid non-Overloaded).
  2. Evaluasi Fitness (Makespan untuk Fog; kombinasi Delay & Energy untuk Fog-Cloud) -> simpan best(x).

STEP 4: Loop Optimasi AOA (C_Iter = 1 s.d. M_Iter = 30)
  1. Hitung MOA(C_Iter) dan MOP(C_Iter).
  2. Untuk tiap solusi i dan tugas j, bangkitkan r1, r2, r3 di [0, 1]:
     - Jika r1 > MOA (Eksplorasi): r2 < 0.5 -> Pembagian (/), else Perkalian (*)
     - Else (Eksploitasi)        : r3 < 0.5 -> Pengurangan (-), else Penjumlahan (+)
     - Diskretkan & klip posisi ke rentang indeks VM valid [LB, UB].
  3. Evaluasi ulang Fitness (dengan penalti jika melanggar kapasitas prediksi Markov) & perbarui best(x).

STEP 5: Eksekusi Jadwal
  Terapkan best(x) ke VM tujuan dan hitung Makespan, Delay, Throughput, Energy, serta PIR.

📚 Glosarium Tanya Jawab (Q&A Dosen)

  • Makespan: Total waktu dari tugas pertama dimulai hingga tugas terakhir selesai.
  • Delay (Latency): Waktu tunda sejak tugas dikirim perangkat IoT hingga selesai diproses.
  • Throughput: Jumlah tugas selesai per satuan waktu ($\text{Throughput} = \sum \text{ExeTime}(t_i)$).
  • PIR: $\text{PIR}(\%) = \frac{Y - Y'}{Y} \times 100\%$ (persentase peningkatan performa terhadap pembanding).
  • Memoryless Property & MIPS: Status berikutnya hanya bergantung pada status saat ini; MIPS = Million Instructions Per Second.
